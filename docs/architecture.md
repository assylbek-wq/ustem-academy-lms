## Модель данных

Program -> Level -> Module -> Lesson -> QuizQuestion, LessonMaterial
Level -> Assignment -> RubricCriterion
Cohort (программа, уровень, версия, заказчик, тренер, язык, даты) -> Enrollment (слушатель, наставник)
Enrollment -> LessonProgress, Evidence (попытки) -> EvidenceFile -> TimecodeComment; Evidence -> Review
Cohort -> Session -> Attendance
Certificate - снапшот ФИО, программы и уровня: проверка по QR работает даже после правок программы.
Служебные: User, UserRole (роль + заказчик), Customer, Upload, AiMessage, Notification, Lead, AuditLog.

## Ключевые решения

- **Загрузка видео** идет частями по 5 МБ (`PUT /api/uploads/<id>?offset=N`). Сервер принимает часть, только
  если `offset` совпадает с уже полученным объемом, иначе возвращает фактический объем, и клиент продолжает
  с нужного места. Идентификатор загрузки хранится в браузере, поэтому повторный выбор того же файла докачивает его.
- **Видео отдаются** через `/files/<id>` с проверкой доступа (владелец, его наставник, тренер когорты, админ)
  и поддержкой Range, чтобы перематывать без скачивания целиком.
- **Посещаемость** отмечается сразу, а без связи складывается в очередь браузера и отправляется при появлении сети.
- **Заказчик** видит ФИО, организацию и прогресс, но не email слушателей. Согласие на передачу сведений
  заказчику берется при регистрации.
- **Видео с детьми** не попадают в публичное портфолио; при загрузке учитель подтверждает согласие родителей.
